    How It Works

    Process lifecycle

    When a process is created, it starts in the NEW state and is admitted to the ready queue after being accepted by the OS.

    Ready queue

    Processes waiting for CPU time are placed in READY, from where the scheduler selects the next process according to dispatch policy.

    CPU scheduling

    Round Robin is a preemptive policy that allocates a fixed time quantum to each process before the OS requeues it.

    Context switching

    Switching from one process to another saves the running context and restores the next task so the CPU remains busy.

    I/O waiting

    When a process requests I/O, it moves to WAITING until the device completes the operation and the process returns to READY.

    Termination

    After the CPU burst finishes or the OS kills the process, it reaches TERMINATED, which is a permanent final state.
